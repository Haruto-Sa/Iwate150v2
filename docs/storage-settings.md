# Storage設定

バケット名と署名URLの有効期限は `src/lib/storage.ts` で解決し、サーバーとブラウザーの署名処理から共用します。

| 設定 | 解決規則 |
| --- | --- |
| バケット名 | `NEXT_PUBLIC_SUPABASE_STORAGE_BUCKET` → `SUPABASE_STORAGE_BUCKET` → `iwate150data`。未定義だけをフォールバックし、空文字は保持 |
| 署名期限 | `NEXT_PUBLIC_SUPABASE_SIGNED_URL_EXPIRES_IN`。既定21600秒、整数化して3600〜86400秒。非有限値は21600秒 |

既存互換のため、サーバー側はモジュール読み込み時、ブラウザー側は署名要求時に設定を評価します。公開URLの生成、非ASCIIパスの変換、キャッシュ、署名失敗時の復帰処理は変更していません。サーバーとブラウザーのキャッシュはそれぞれの環境で保持します。

22件の特性テストを本番コード変更前に通し、同じテストを集約後にも実行しています。環境変数の優先順位、空文字、期限の上下限、キャッシュ更新、公開URL・署名APIへの引数を確認します。

```sh
bun run test:unit -- src/lib/storage.test.ts src/lib/storageSignedClient.test.ts
```

管理用CLIスクリプトの環境変数解決はこのアプリ実行時の設定集約に含みません。実際のStorage環境やバケットの権限設定は変更しません。

検証: 全単体643件、型検査、本番ビルド、関連ブラウザーテスト89件が成功（タッチ端末プロファイルのホイール操作2件は対象外）。署名APIはモックで確認しており、実Storage・実機での検証は含みません。ブラウザーの確認範囲は画像プレビュー、画面遷移、モデル通信失敗からの再試行などです。
