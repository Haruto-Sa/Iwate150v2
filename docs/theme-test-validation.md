# テーマ検証のDOM取得

メディアと祖先要素の `filter` を調べるときは、DOM取得とスタイル評価を同じ `page.evaluate` 内で実行します。3Dモデルの読み込みでcanvasが置換されるため、先に取得した要素ハンドルを後から評価すると、切断済みの要素の空のcomputed styleを異常と判定する場合があります。

WebKitの隔離ページでcanvasを差し替える試験を150回行ったところ、`locator.evaluateAll` は12回、切断済み要素の `filter: ""` を返しました。同じ評価内でDOM取得も行う方法では0回でした。元のCI失敗も `/character` のモデル読み込み中に発生していましたが、元の記録にはfilterの実値がないため、この再現結果と区別します。

判定基準は従来どおり、メディア自身と祖先の `filter` がすべて `none` であることです。空文字や特定フィルターの除外、リトライ、期限延長は加えません。失敗時には画面・要素・祖先・実値を出力します。

修正後の明暗テーマ×Chromium/WebKit/iPhone/Androidプロファイル8件は成功（41.5秒）。実際のE2E判定式を隔離ページで実行し、無加工は空一覧、祖先の `invert(1)` とcanvas自身の `blur(1px)` は異常として検出しました。2回目の要素置換試験でも従来5/150回・変更後0/150回でした。アプリの表示コードは変更していません。
